### 重启存活一节的边界（必须一起看）

ColorOS 的开机广播是**延迟投递**的：系统 15:00:28 post，App 15:04:17 才收到（约 3 分 49 秒）。落在窗口内的短信会被 ROM 直接丢弃，实证：

```
15:03:39.203 W OplusAppStartupManager: sikp broadcast for proc does not exist,
             pkg:com.elysia.smsrelay, action:android.provider.Telephony.SMS_RECEIVED
```

即：**重启后 3~4 分钟内到达的短信会丢**（App 进程尚未被拉起，ColorOS 不为广播冷启动它）。窗口之外一切正常。缓解手段见「已知限制」。

## 三、已知限制与后续

1. **重启窗口丢信**：重启后 3~4 分钟内到达的短信会被 ColorOS 丢弃（App 未起、ROM 不为广播冷启动）。缓解：重启后手动开一次 App；或把副机长期不断电。彻底解法需要 ROM 侧放行（已开三开关仍不足）或换非 OPPO 机型。
2. **双卡未验证**：仅一卡在位，SIM2 路径只做了代码级兜底（Intent extra → SubscriptionManager → 未知），未真机验证。
3. **图标隐藏/伪装未做**（验收项 7）：v0.1.0 未实现，老人机部署前需要补。
4. **主端未做**：主机（Android 11）侧的接收端尚未开始；当前可用任意 webhook 接收端或 Bark 顶替。
5. **明文 HTTP 允许**：为局域网直推与 adb reverse 保留；走公网第三方通道时建议填 https 地址。
6. **adb 安装通道**：ColorOS「电脑端安装」在本机已卡死（会话提交后永不落地），后续迭代改用手机端侧载。

## 四、复现方式

```
构建：cd D:\dshproject\sms-relay && .\gradlew.bat :app:assembleRelease
接收端：node _test/webhook-server.mjs            # 监听 127.0.0.1:8787，逐条落盘到 _test/webhook.log
链路：adb reverse tcp:8787 tcp:8787             # 手机侧 127.0.0.1:8787 → PC
注入（仅 debug 包）：
  adb shell am broadcast -a com.elysia.smsrelay.DEBUG_INJECT \
    -n com.elysia.smsrelay.debug/com.elysia.smsrelay.DebugInjectReceiver \
    --es sender 10086 --es body "您的验证码是 483920，5分钟内有效。"
读库：adb exec-out run-as com.elysia.smsrelay.debug cat databases/smsrelay.db > relay.db（仅 debug 包可读）
```
