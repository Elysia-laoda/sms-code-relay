首个可用版本：**sender v0.3.0 + receiver v0.2.1**（两端真机端到端跑通）。

## 装哪个

| 文件 | 装在哪 | 说明 |
|---|---|---|
| `sender-v0.3.0-release.apk` | 副机（插副卡那台） | 收短信 → 过滤 → 邮箱/HTTP 转发 |
| `receiver-v0.2.1-release.apk` | 你的主机 | 邮箱轮询 / 局域网接收 → 通知 + 悬浮窗 |

**用「文件管理」侧载安装**，不要用 `adb install`（ColorOS 上会卡死，见 README 第 3.3 节）。装完记得把应用加进系统的**自启动 / 后台白名单**。

## 这一版做到了什么（实测）

- 真机端到端：副机收短信 → 发送端 SMTP → 自有邮箱 → 接收端 POP3 取回 → 记录 + 横幅通知 + 悬浮窗，**一个轮询周期内到位**（默认 20 秒，实测 26 秒）。
- 过滤：正例 4 条转发、反例 2 条不转（无关键词/命中排除词）。
- 重试：通道不可达时指数退避，恢复后自动补发；跨进程重启后队列仍会继续。
- 开机存活：重启后 3 分 49 秒自动拉起服务（全程无手动操作）。

## 为什么用邮箱通道

国产 ROM 对第三方 App 发短信**逐条弹系统确认**（`Permission Intercept`），`cmd role` 授短信角色也被拒；而 `ntfy.sh` / `broker.emqx.io` 在国内移动网络下**根本不通**，Bark/Server酱/企业微信机器人**只能发不能拉**。把中转放在你自己的邮箱里，是这套约束下最省的一条路。完整实测表见 README 第三节与 `docs/`。

## 已知限制

- 只在单卡环境验证过，SIM2 路径未实测；图标伪装/勿扰策略未实现。
- 邮箱通道时延下界 = 轮询间隔（可调 5~600 秒）；要更快用局域网通道。
- POP3 是「取走即删」语义，多客户端同读一个邮箱时慎用。
